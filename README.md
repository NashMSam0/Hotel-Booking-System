# Kudzis Bookings — Rooms + Activities + Dining

Explicit split:

- **Backend** = `HotelBooking.Api` (ASP.NET Core 8 Web API: Identity + JWT, EF Core, Swagger, Razor ops dashboard)
  + `HotelBooking.Data` (`HotelDbContext : IdentityDbContext`, seed: room types, rooms, 5 Zim activities, tables)
  + `HotelBooking.Core` (pricing, overlap checks, payment + reference helpers)
- **Frontend (guest site)** = `HotelBooking.Client` (Angular standalone, public: landing page, rooms search/book + calendar, activity slots, lunch/dinner tables, my-bookings + payments)
- **Frontend (staff console)** = `HotelBooking.Web` (Angular standalone, internal ops: bookings console, catalog management, reports; Admin/Staff roles only)
- **Backend** = `HotelBooking.Api` (ASP.NET Core 8 Web API: Identity + JWT, EF Core, Swagger, Razor ops dashboard)

```
HotelBooking/
  HotelBooking.slnx
  HotelBooking.Api/     <- backend (controllers: auth, rooms/room-bookings, activities/activity-bookings, dining)
  HotelBooking.Data/    <- backend (entities + DbContext + migrations)
  HotelBooking.Core/    <- backend (shared logic)
  HotelBooking.Client/  <- public guest site (deploy this to Vercel)
  HotelBooking.Web/     <- staff ops console (run locally, do not publish publicly)
```

## Run backend
```powershell
dotnet ef database update --project HotelBooking.Data --startup-project HotelBooking.Api
dotnet run --project HotelBooking.Api
# Swagger: https://localhost:7064/swagger
# Seed admin: admin@hotel.local / Admin123!
```

## Run frontend (guest site)
```powershell
cd HotelBooking.Client
npm install
npm start     # ng serve --proxy-config proxy.conf.json -> https://localhost:7064
# http://localhost:4200
```

## Run staff console
```powershell
cd HotelBooking.Web
npm start     # internal ops console (Admin/Staff login)
# http://localhost:4200 (or ng serve --port 4201 to run alongside the guest site)
```

## Key rules (verified end-to-end)
- Rooms: overlap blocked (409) — `CheckIn < existing.CheckOut && existing.CheckIn < CheckOut`
- Activities: capacity check per `SlotStart`, `SUM(participants) <= Capacity`
- Dining: `MealType 0=Lunch/12:30, 1=Dinner/19:30`, table clash per date+meal, `Seats >= PartySize`
- Auth: register assigns `Guest`; admin seeded; cancel allowed for owner or Admin/Staff

## Deploying the backend free: Render (API) + Supabase (Postgres)

Vercel/Firebase cannot run ASP.NET Core, and Render's own free Postgres expires
after 30 days — so the no-card combo is Render for the API + Supabase for the DB.
(Fly.io/Cloud Run also work but need a credit card; Azure F1 + free SQL is the
no-code-change alternative if you have a card.)

1. **Supabase**: new project → Settings → Database → copy the **direct**
   connection string (port 5432, not the pooler) — the app creates the schema
   itself on first boot (`Database:Provider=Postgres` → `EnsureCreated`).
2. **Render**: New → Blueprint → point at this repo (`render.yaml`). Fill
   `ConnectionStrings__Default` (Supabase string), replace
   `Cors__AllowedOrigins__0` with your Vercel URL. Deploy (~5 min first build).
3. Open `https://kudzis-api.onrender.com/api/rooms` → 5 rooms = API + DB up.
   First hit after 15 min idle takes ~1 min (free-tier cold start); a free
   cron-job.org ping every 10 min keeps it warm.
4. Vercel: set `apiBaseUrl` in `environment.prod.ts` to
   `https://kudzis-api.onrender.com/api`, push — frontend redeploys.

Notes: `Jwt__Key` is auto-generated by Render; rotate the seeded
`admin@hotel.local / Admin123!` account after first login; switch
`Email__Method` to `Smtp` (e.g. free Brevo) before real guests arrive.

## Deploying the frontend to Vercel
Vercel hosts the Angular app only — the ASP.NET API + SQL Server must live
elsewhere (e.g. Azure App Service + Azure SQL).
1. Host `HotelBooking.Api` publicly with a SQL database, run `dotnet ef database update`
   against it, and add your Vercel domain to the `ng` CORS policy in `Program.cs`.
   Override `Jwt:Key` and `ConnectionStrings:Default` via host env vars (do not
   ship the dev values in `appsettings.json`).
2. Put the public API URL into `HotelBooking.Web/src/environments/environment.prod.ts`
   (`apiBaseUrl`, e.g. `https://kudzis-api.azurewebsites.net/api`).
3. On Vercel: Import the GitHub repo → Root Directory `HotelBooking.Client` →
   Build Command `npm run build` → Output Directory `dist/HotelBooking.Client/browser`
   (`vercel.json` in that folder already sets this + SPA rewrites).
